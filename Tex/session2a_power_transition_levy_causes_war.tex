\section{Data Collection}
Data collection phase for this project began with the collection of data for the House of Commons and continued with collection of data for the House of Lords. While the first step relied on the data collection of \textcite{blumenauHouseCommonsParliamentary2021}, the second step was more complex. I replicated for the Lords the same data and variables that \textcite{blumenauHouseCommonsParliamentary2021} provides for the House of Commons. This meant downloading the variables at the members level as first step. I then retrieved the speeches data. Since the identifiers of the two different data collections do not match exactly, a further step included the match of these identifiers. The last step was the merge of the two different collecions of Lords data, so that I could have the same structure of \textcite{blumenauHouseCommonsParliamentary2021} but for Lords. Eventually I could merge the data of the Members of the House of Commons with the data of Members of the House of Lords.

\subsection{Collection of Lords Data}
In order to retrieve the covariates of my analysis I used the Python package pdpy from \textcite{HouseofcommonslibraryPdpyPython}. This package was written for downloading data from the UK Parliament's data platform. A Python file the pipeline uses this package to retrieve the data for the selected period from the API of UK Parliament's data platform. This file downloads four different datasets in comma separated value format. Each of these datasets contains different kinds of information about the Members of the House of Lords that were in office for at least one day in the period of analysis (1979-1990). In order to correctly match the data of the members, four varaibles are downloaded in each datasets. Thus, these variables serve as common identifier that uniquely matches the values of the rows in all of the datasets. The variables are: "person\_id", "mnis\_id", "given\_name", "family\_name", "display\_name".
The dataset called "personal\_data" contains the following variables: "other\_names", "full\_title", "gender", "date\_of\_birth", "date\_of\_death". They were used to identify the Lords in the in the UK Parliament platform (\textcite{MPsLordsUK}).

The dataset called "seat\_type" contains the following variables: "seat\_type\_name",\\"seat\_incumbency\_start\_date", "seat\_incumbency\_end\_date". They are used in the preliminary statistics and in the causal analysis because the literature on linguist complexity in parliament highilighted their importance. While the first variable is string, the two others variables are date type. Since interventions in the House of Lords are correctly associated with the date I used "seat\_incumbency\_start\_date" and "seat\_incumbency\_end\_date" to identify from what position do the Member of Parliament spoke. They are also important to describe the relative power inside the opposition.

The dataset called "parties" contains the following variables: "party\_id", "party\_mnis\_id", "party\_name", "party\_membership\_id", "party\_membership\_start\_date",\\"party\_membership\_end\_date". Labour and Conservatives were and are the two most influential parties in the UK. However, this dataset reveals a number of smaller parties and a more complex party system. Again this data are used to identify the leading party and the period in which each member belonged to a party. At some point of the debate on television broadcasting the issue became politicisised and Labours at the opposition supported it, while Conservatives in the governament did not.% Qui andrebbe inserito il collegamento alla sezione in cui questa analisi verrà fatta
These data will be used to produce descriptive statistics about party membership and linguistic complexity. These variables will also be included in the causal analysis.

The dataset called "government\_position" contains the following variables: "position\_id", "position\_name", "government\_incumbency\_id","government\_incumbency\_start\_date",\\"government\_incumbency\_end\_date". Since interventions in the House of Lords are correctly associated with the date I used "government\_incumbency\_start\_date" and "government\_incumbency\_end\_date" to identify when the Member of Parliament spoke as member of governament or as opposition member. They describe the Member's position, and thus to whom do they refere to in their speeches, be it their own constituency or a broader audience, such as the whole electorate itself (\textcite{spirlingDemocratizationLinguisticComplexity2016}).

\subsection{Incoherence in the Data}
At a first glance, data from the pdpy package seem complete and coherent. In each commma separated value dataset each column is a variable and each row contains the data of a single Member of the House of Lords. However, in "seat\_type" there are 1342 row but only 1340 unique identifiers; in "government\_position" there are 25 row but only 17 unique identifiers; in "parties" there are 25 row but only 17 unique identifiers. % bisogna vedere la differenza tra anagrafica e partiti
Some times Members have more than one government position or changed parties or covered more than a parliamentary office during their mandates. In these cases the pdpy package adds one row to record the second government position, the second party or parliamentary office. I recoded the variables so that all data that belong to a single identifier are stored in one raw. The files that do these changes are 03\_errors\_in\_lords\_data.py for "seat\_type" and "government\_position".

03\_errors\_in\_lords\_data.py removes Oliver Eden's (mnis\_id 2616) second row marked by "excepted hereditary record". It also combines Frederick Coggan's two membership records (mnis\_id 3409). Frederick Coggan has tow rows in "seat\_type". The first one provides the the data for the period when he was bishop. The second one provides the the data for the period when he became life peer. The dates show that he bacame life peer soon after "resigning" as bishop. There are five identifiers (1722, 2761, 2221, 3493, 3527) which have more than one row. All the entries are coherent with bibliographic data from the UK Parliament platform \textcite{MPsLordsUK}. Multiple rows for these members simply reflect the fact that coverd more than one position in the government.

"04\_errors\_in\_lords\_data2.py" details the changes made to the "parties" dataset. In order to find the correct data on Members, I checked the entries with bibliographic data from the UK Parliament platform \textcite{MPsLordsUK}.

After completing the previous data manipulation the it is possible to merge the data through "06\_lords\_data\_merge.py".
The data are complete and coherent. In "lords\_data\_merged.csv" each column is a variable and each row contains the data of a single Member of the House of Lords.

\subsection{Speeches Data}

Our source of data is the Hansard Archive \textcite{HansardUKParliament}. This archive is the official report of the UK Parliament debates. It has a collection of digitalised data accessible through its \textcite{HANSARD18032005}. \subsection{Merging Lords Data with Speeches}
As alreay mentioned at the beginning of this chapter, in order to have a complete collection of data and speeches of the Members of the House of Lords, we still need to match the data about the Members and the interventions they made in the House. In this way, we will have data comparable to the ones of \textcite{blumenauHouseCommonsParliamentary2021}. On one side,
"person\_id", "mnis\_id", "given\_name", "family\_name" and  "display\_name" are the variables that uniquely identify a Member of the House of Lords in the data downloaded with the pdpy package. In "personal\_data" there are other variables that describe Members' names: "other\_names" and "full\_title". These variables are correctly and uniquely matched to the identifiers.
On the speeches side, we have "hansard\_name", "hansard\_person\_slug" and "slug\_test".

The script "07\_lords\_data\_and\_speeches\_merge.py" implements a reproducible record linkage procedure that connects speaker identifiers in the "hansard\_lords\_1979\_1989\_slug\_test.csv"% attenzione alle date
to MNIS identifiers in "lords\_data\_merged.csv". Its purpose is to construct a correspondence dictionary that can support subsequent integration of parliamentary speeches with individual characteristics, while preserving the original records and documenting the basis of each linkage decision.

The script retains the identifier’s provenance because "slug\_test" and "hansard\_person\_slug" differ in their construction and potential exposure to attribution errors. Although "hansard\_name" is preserved for reference and export, it is not independently compared during matching. Interventions are grouped according to the identifier used—either "hansard\_person\_slug", when unavailable, "slug\_test"--and its exact value before normalization. Each group retains all distinct recorded speaker names, valid intervention dates, the total number of interventions, the number of missing or invalid dates, and any previously assigned MNIS identifiers. For example, "mr\-john\-palmer\-2` is the original value, whereas `john palmer` is the normalized form used for comparison. Grouping takes both elements into account: two interventions belong to the same group only if their identifiers come from the same variable and have exactly the same original value. Consequently, identical values originating from different identifier variables form separate groups.

Candidate identities are retrieved through exact equality between normalized identifier variants and an index of member names and titles. Normalization standardizes case, removes diacritical marks, separates words by discarding punctuation, excludes specified English stop words, and removes recognized initial forms of address. Additional rules standardize selected parliamentary and ecclesiastical titles and remove listed terminal honours. The member index incorporates display names, full titles, given names combined with surnames, and fuller personal names where additional name components are available.

Alternative queries may omit an initial parliamentary rank when sufficient name components remain, while avoiding searches based solely on a surname obtained by removing a title. Numeric suffixes are removed from original Hansard slugs for comparison, but distinct observed slugs sharing the same resulting base are withheld from automatic assignment to prevent the normalization process from conflating separate source identifiers.

Textual correspondence is subsequently evaluated against temporal evidence. For every valid intervention date, candidates are classified according to whether their recorded Lords membership intervals confirm their presence, contradict it, or provide insufficient information; available birth and death dates supply further exclusion criteria. Membership boundaries are inclusive, and an interval with a known start but no end is treated as open-ended.

Automatic assignment requires one uniquely eligible, temporally confirmed candidate on every intervention date and the same MNIS identity throughout the group.

A candidate with unknown membership remains non-excludable and can therefore prevent an otherwise plausible assignment. Missing or invalid intervention dates, incompatible membership histories, identities that change across dates, and conflicts with existing MNIS assignments likewise leave the group unresolved. Existing identifiers function as consistency checks rather than independent grounds for acceptance. When no exact textual candidate exists, approximate string comparison supplies suggestions for manual inspection; these suggestions never produce automatic matches, and their similarity threshold is not interpreted as an identity probability.

The script exports accepted correspondences to matched.csv, unresolved cases to unmatched.csv, and group-level evidence and decision reasons to matching\_report.csv. Distinct original speaker-name variants are retained, allowing multiple dictionary rows to refer to the same individual. The resulting dictionary represents a date-invariant association between identifiers rather than a speech-level merge, so titles referring to different individuals over time remain unresolved.
